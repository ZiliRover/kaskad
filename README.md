# Каскад (рабочее название)

Нодовая веб-студия для AI-видео и изображений: промты, картинки и модели соединяются в цепочки
на холсте. Видение продукта и планы — в [PRODUCT.md](PRODUCT.md).

## Запуск

**С кнопки:** двойной клик по `start-studio.bat`. При первом запуске он сам поставит зависимости
и создаст `.env`, затем поднимет студию и откроет браузер. Если студия уже запущена, просто откроет её.
Остановить: закрыть окно или Ctrl+C.

**Вручную.** Нужен Node.js 20+.

```bash
npm install
cp .env.example .env    # вписать OPENROUTER_API_KEY
npm run dev             # база + сайт + воркер генераций
```

Открыть http://localhost:3000.

`npm run dev` поднимает три процесса:

| процесс | что делает |
|---|---|
| `db` | локальный Postgres (пакет embedded-postgres, данные в `.pgdata/`), применяет миграции |
| `web` | Next.js: холст и API |
| `worker` | выполняет генерации из очереди |

**Тестовый режим.** По умолчанию `PROVIDER_MODE=mock`: генерации ненастоящие и бесплатные,
в шапке висит плашка «Тестовый режим». Для реальных генераций — `PROVIDER_MODE=live`
(тратит деньги с баланса OpenRouter). В тестовом режиме слово `[fail]` в промте имитирует ошибку модели.
Тестовое «видео» — любой mp4, путь к нему в `MOCK_VIDEO_PATH` (в git образца нет, он слишком тяжёлый).

Если после аварийного завершения Postgres остался висеть: `npm run db:stop`.

## Команды

| команда | |
|---|---|
| `npm run dev` | всё для разработки |
| `npm run models:sync` | подтянуть параметры и цены моделей с OpenRouter |
| `npm run db:generate` | создать миграцию после изменения `src/server/db/schema.ts` |
| `npm run typecheck` / `npm run build` | проверка типов / продакшн-сборка |

## Что умеет

- Цепочки промт → картинка → видео → текст; входы и параметры нод строятся из реестра моделей.
- Цена до запуска на каждой ноде и подтверждение с суммой, если запускается больше одной ноды.
  Цены в рублях по курсу ЦБ (себестоимость, наценка появится вместе с кредитами), в подсказке сумма в $.
- Генерации идут на сервере: вкладку можно закрыть. Кнопка «Стоп» отменяет задачу в очереди бесплатно,
  а идущую генерацию останавливает с предупреждением, что провайдер мог уже начать списание.
- История результатов у каждой ноды (стрелки «2 из 3»). Дальше по цепочке идёт последняя версия.
- Удаление нод и связей отменяется кнопкой «Вернуть» или Ctrl+Z.

## Как устроено

- **Холст** — React Flow. Ноды моделей не пишутся руками: входы и параметры строятся из реестра моделей.
- **Реестр моделей** — `src/lib/models/`. `curation.ts` решает, *какие* модели мы предлагаем и как их называем;
  `catalog.json` (генерируется `models:sync`) хранит их реальные возможности и цены.
  **Добавить модель** = строка в `curation.ts` + `npm run models:sync`.
- **Запуск** — `src/lib/graph/plan.ts` решает, какие ноды выполнить и в каком порядке. Одна и та же функция
  считает цену для подтверждения в браузере и строит план на сервере.
- **Очередь** — задачи в Postgres (`jobs`), воркер забирает их через `FOR UPDATE SKIP LOCKED`.
  Для видео id задачи у провайдера сохраняется сразу, поэтому перезапуск воркера продолжает ожидание,
  а не оплачивает генерацию второй раз. Если входная нода упала, зависимые помечаются с понятной причиной.
- **Результаты** — таблица `outputs` и файлы в `storage/`. История не теряется: неудачный перезапуск
  не стирает прошлый результат.
- **Провайдеры** — `src/server/providers/`: OpenRouter (картинки через `/images`, видео через `/videos`,
  текст через `/chat/completions`) и mock. Сюда же добавятся fal.ai, Replicate и прямые API.

```
src/
  app/            страницы и API (graphs, runs, uploads, files)
  components/     интерфейс студии
  lib/            общее для браузера и сервера: граф, план, модели, цены
  server/         база, хранилище, провайдеры, воркер
scripts/          dev-Postgres, синхронизация моделей
drizzle/          SQL-миграции
prototype/        прежний десктопный прототип (pywebview), только для справки
```
